# Industrial Routing Lab v1.0.0: OSPF, BGP and WAN Failover

First validated release of an isolated industrial routing lab built with Containerlab and FRRouting 10.7.1.

## Features
- Six FRRouting routers and two Alpine Linux hosts in a reproducible Containerlab topology
- OSPF Area 0 interconnecting the core and two edge routers
- Dual eBGP uplinks with simulated ISPs and a transit autonomous system
- Inbound and outbound BGP prefix filters with conditional default-route origination
- Preferred routing through Edge A, with backup through Edge B
- Automated startup configuration loading, routing verification, and controlled WAN failover testing
- English network documentation, addressing plan, troubleshooting guide, and CLI evidence screenshots

## Verified results

The [successful live routing CI run](https://github.com/ModarRostom/industrial-ospf-bgp-lab/actions/runs/42273117707) on November 6, 2026 confirmed:

- **PASS:** Both core OSPF neighbors reached Full state
- **PASS:** OSPF default route selected via Edge A
- **PASS:** BGP plant prefix installed on the transit router
- **PASS:** Bidirectional ICMP connectivity between plant and service
- **PASS:** Primary uplink failure switched the core to Edge B
- **PASS:** The external service remained reachable (3/3 ICMP replies, 0% loss in the post-failover ping)
- **PASS:** Restoring the primary uplink returned the core to Edge A

[Static configuration and shell syntax checks](https://github.com/ModarRostom/industrial-ospf-bgp-lab/actions/runs/42273117662) also passed.

## Scope

All complete routing and failover checks were validated on a GitHub-hosted Ubuntu runner using a simulated Containerlab network. Windows/WSL was used for a separate successful eight-container deployment, not the full verified failover test. This laboratory release does not imply production readiness, a failover SLA, or guaranteed convergence times.
